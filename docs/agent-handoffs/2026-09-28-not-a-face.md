## Task

- **Title:** NOTFACE - no non-face, low-detection or heavily blurred stranger photos; retire the stored ones
- **Owner/agent:** INT (integrator), Claude session
- **Acceptance criteria:**
  - Owner: "remove all this, not face" (a stored stranger capture of a bowed head), then "remove blur and lower detected too".
  - New stranger photos are stored only above a detector-confidence floor and a heavy-blur floor, in both engine flows.
  - Recognition, grants and door decisions are unchanged.
  - Stored captures can be retired as "not a face" without rewriting the DENIED access events, and the retirement can be undone.

## Changes

- **Files changed:** listed above, plus server.ts.
- **Behavior changed:**
  - **Legacy flow** (`applyRecognitionOutcome`): a stranger whose observation has a detector score below `FACE_STRANGER_MIN_DETECTOR_SCORE` (0.80) is suppressed as `stranger-not-face`. One whose aligned-face edge energy is below `FACE_STRANGER_MIN_EDGE_ENERGY` (0.16) is suppressed as `stranger-blur`.
    - Same semantics as the existing `stranger-quality` and `stranger-small` floors: counted in the gate's `strangersSuppressed`, no row or photo written.
    - Suppressions from the manual scan API are counted in a throwaway, as before.
  - **Pipeline flow** (`TrackDecision`): a track whose best frame's detector score is below the same env value ends `insufficient` (basis `insufficient-quality`) instead of `stranger`.
  - **Recognition unchanged:** employees are matched and granted exactly as before. Unit test: an employee is still recognised at detector score 0.6.
  - **Engine:** `ExtractedFace.edgeEnergy` (new, additive) is the mean squared central-difference gradient over the central 70% of the aligned 112×112 face, divided by that area's intensity variance. Only the storage floor reads it.
- **API/event contracts added or changed:**
  - `POST /api/strangers/retire-non-faces` `{ logIds: string[1..500], reason?: string, dryRun?: boolean }`, admin only (explicit auth rule), CSRF.
    - Returns `{ clusterId, retired, skipped: { invalid, notCandidate, alreadyRetired }, resolution }`, or with `dryRun`: `{ wouldRetire, skipped }`.
    - Writes one append-only DISMISS resolution per batch: `clusterId NOTFACE-<uuid>`, `metadata.kind "not-a-face"`, actor from the session.
    - Broadcasts SSE `stranger_dismissed`.
    - Undo with the existing `POST /api/strangers/restore { clusterId, clusterLogIds }`.
  - New `OutcomeSuppression` values `stranger-not-face` and `stranger-blur` in the watch stats (`lastSuppressed`).
- **Schema/migration changed:** none. Uses the existing `stranger_resolutions` table.
- **Environment/configuration changed:** `FACE_STRANGER_MIN_DETECTOR_SCORE` (default 0.80, 0 disables) and `FACE_STRANGER_MIN_EDGE_ENERGY` (default 0.16, 0 disables), passed through docker-compose.yml and documented in .env.example.
- **Security/privacy impact:** collects less biometric data. The retirement route is admin-only, actor-attributed, append-only, and never deletes the access event or its photo.

## Calibration (site captures, 2026-09-28)

- 287 DENIED captures from 28 Sep, 264 with a re-detected face.
  - Detector score below 0.70: nearly all unusable (bowed heads seen from above, hands over faces, profiles, masks, motion blur, a cardboard box).
  - 0.70–0.76: about 8/32 usable. 0.77–0.80: about 40% usable. 0.80 and above: mostly real faces.
  - The 0.80 floor drops 111 of 264.
- Laplacian sharpness (the existing `sharpness`) does not see motion blur. Edge energy below 0.16 catches 6/19 visibly blurred faces and drops 2/45 clear ones, so it catches HEAVY blur only.
- The live floor scores the original frame; the calibration re-scored the stored (possibly downscaled) photos, so the live floor is slightly more lenient than the calibration.
