### Design notes

- `latest()` returns null before the first frame, while not streaming, and when the newest frame is older
  than `staleMs`. "frame" is emitted for every delivered frame; consumers should do no heavy work in the
  listener and should pull `latest()` on their own cadence (never queue). A throwing listener cannot break
  the reader.
- When one stdout read contains a complete frame followed by another complete frame, the older one is
  skipped without copying (`seq` still counts it, so gaps show drops). With large frames (4K = 24.9 MB,
  pipe reads of 64 KB) this rarely triggers; the real protection is the pull model plus FFmpeg's bounded
  queues.
- `-fps_mode passthrough` was added (not in the brief): rawvideo output defaults to CFR, which duplicated
  the first decoded frame back to t=0 (a burst of up to one GOP of stale copies, ~30 frames on entry,
  after every connect) and filled stalls with copies. It also halved entry decode delay (below).
- `firstFrameTimeoutMs` (default 10 s) covers connect + first keyframe (entry GOP ~4 s); the 1 s stale rule
  applies only once streaming. Back-off resets after 10 s of healthy streaming.
- ROI is clamped to the source and rounded to even pixels (exact 4:2:0 crop); the full frame is still
  cropped explicitly so a smaller-than-configured source fails loudly instead of mis-slicing. A source
  LARGER than configured is not detected (use `probeStreamSize` at start).
- Motion: 64-wide gray thumbnail from 3×3 samples per cell (~21k reads per frame regardless of ROI size),
  cell changed if |Δ| > 12, motion if ≥ 0.5 % of cells changed, held for 2 s. Fails open (first frame,
  after reconnect, unknown frame → moving). Not tuned on real footage yet.
- The brief's `-skip_frame nonref` is not a valid FFmpeg value (every start fails with "Unable to parse
  option value"); the AVDiscard name is `noref`. Allowed values are whitelisted.

|---|---|---|---|---|---|---|---|
| entry 4K | default (low_delay, full frame) | 4.6 s | 7.83 | 68 / 232 / 812 ms | 194 / 423 ms* | 1.20 | 0.23 |
| entry 4K | ROI 1600×1600 | 2.8 s | 8.00 | 65 / 167 / 277 ms | 149 / 194 ms | 0.98 | 0.10 |
| exit 1080p | default (low_delay, full frame) | 2.5 s | 7.99 | 61 / 135 / 234 ms | 49 / 147 ms* | 0.57 | 0.09 |

*from the `--latency` run of the same variant (first frame 1.8 s in both).

Reading the numbers:
- First-frame time is dominated by where in the GOP the connect lands (entry GOP 4 s, exit 2 s): 0.7-4.8 s.
  This is paid once per connect now, not once per look.
- `-skip_frame noref`: no gain (IP-only camera streams have no non-reference frames).
- 4K HEVC at 15 fps single-threaded (`low_delay`) costs ~54 ms CPU per frame (file benchmark: 20 fps max
  on one core), i.e. ~75 % of one core: close to saturation, so queueing shows up as decode delay. Full-frame
  4K RGB24 output (24.9 MB/frame, ~200 MB/s through the pipe) adds ~0.2 core in FFmpeg and ~0.25 core in
  Node. **Recommendation for entry: always set a gate-area ROI** (−0.2 core FFmpeg, −0.15 core Node, decode
  delay p50 ~150 ms); if the full frame is needed, use `decoder: { lowDelay: false, threads: 2 }`.
  **Exit: defaults** (low_delay; frame threads add ~80 ms there).
- Estimated pipeline CPU for both gates, reader only: ~1.1-1.8 cores (vs. ~1.4 cores for the whole legacy
  path today); detection comes on top. The ≤ 0.5 core idle target cannot be met by the reader alone while it
  decodes 4K continuously (owner decision: no camera/NVR rate change).
- Newest-frame age as a consumer sees it is ~65 ms median (half a frame interval at 8 fps), p95 ≤ 232 ms.
  Camera-side delay (sensor → encoder → network) is not measurable without a camera clock and is not included.

Recovery (synthetic, exit):
- Publisher stopped for 5 s: FFmpeg exited at once ("404 Not Found" while the path was down, redacted
  `lastError`), reconnects at +1 s, +2 s, +4 s; streaming again 3 s after the source returned; 8 s total gap
  for a 5 s outage.
- Server frozen for 6 s (`docker pause`, TCP open, no data): `stale` after 1.1 s, SIGKILL, reconnect at +1 s,
  streaming again ~1 s after the server resumed.

## Risks and follow-up

- **Known risks:**
  - Real-stream numbers are missing (see above); entry CPU on the real 4K stream may differ from synthetic.
  - Shadow mode runs the legacy grab AND the reader on the same stream: +1 long-lived RTSP session per gate
    on top of the per-look sessions. The NVR session limit is still unknown.
  - Full-frame 4K frames are 24.9 MB each (fresh buffer per frame, ~200 MB/s allocation at 8 fps); keep
    ROIs set and let consumers drop frames they do not keep.
  - Motion thresholds are untuned on real footage (night IR, rain, auto-exposure changes count as motion,
    which only costs CPU).
- **Unresolved questions:** approval to read the camera/NVR login for the real-stream measurement and the
  ISAPI lookup (owner/INT).
- **Dependencies on other agents/commits:** none; codes against W0 `contracts.ts`.
- **Requested integration action/order (proposals for INT, not applied):**
  1. `server.ts` (INT): per gate in `shadow`/`live`, build one reader:
     `createStreamReader({ gate, streamId, url: <gate rtspUrl, server-side>, sourceWidth/Height: from
     probeStreamSize(url) once at start (or config), roi: <gate ROI from camera config, UI step 4>,
     fps: 8, decoder: gate === "ENTRY" && !roi ? { lowDelay: false, threads: 2 } : undefined })`;
     `start()` when the mode becomes shadow/live, `stop()` on switch back to legacy, config change and
     SIGTERM/SIGINT. In `live`, stop the legacy grab for that gate (session count).
  2. Surface `SourceState` (status, fps, newestFrameAgeMs, reconnects, redacted lastError) in the watcher
     status/SSE; treat `stale`/`reconnecting` longer than 10 s as a watcher error (plan target).
  3. Detection loop pulls `latest()` when idle; skips when `motion(frame) === false`, but still runs at least
     once per ~1 s as a keep-alive.
  4. `contracts.ts` (optional): add `getState(): SourceState` to `FrameSource` (implemented already) so the
     watcher panel can poll without listening; and correct plan section 9's `-skip_frame nonref` to `noref`
     (measured: no benefit, so leave it off).
