## Changes

- **Files changed:**
  - `src/components/StrangerClusterModal.tsx`
  - `src/utils/strangerPhotos.ts` (new, pure helpers)
  - `tests/strangerPhotosUi.test.ts` (new)
- **Behavior changed:**
  - Tile identity:
    - Each tile uses `observationIdOf(photo)` for its React key, its `data-observation-id`, the active selection (`activeObservationId` state replaces `activePhotoUrl`) and the "Avatar chính" state.
    - `photoUrl` and the merge-summary thumbnail come from the active tile's `photoSnapshot`.
  - Default chosen tile when a cluster opens, in order:
    1. the preselected tile;
    2. the tile whose `photoSnapshot === cluster.primaryPhoto`;
    3. the first tile.

    Previously, if `primaryPhoto` matched no tile, the request sent `photoUrl=primaryPhoto` with no `sourceLogId`. Now it always names a real tile.
  - Resolve payloads use `...resolvePayloadIds(photos, activePhoto)`:
    - `clusterObservationIds`: one entry per tile.
    - `clusterLogIds`: de-duplicated. The server's `requestedLogIds` already de-duplicates, so this is equivalent for old servers.
    - `sourceLogId` and `sourceObservationId`: for quick-register and merge only.
    - Dismiss sends the cluster ids and no source.
  - Preselection:
    - An in-app photo click matches a tile's `photoSnapshot` first, then its `frameUrl`. A caller holding the event's whole-frame URL still finds the face tile.
    - A log deep link selects the first tile of that log.
    - New optional prop `initialPreselectedFaceId` takes precedence over the log id. It matches `faceId` or `observationId === "face:<id>"`, and falls back to `GET /api/strangers/lookup?faceId=`. Miss notices say "khuôn mặt <id>" or "lượt quét <id>".
  - Whole-frame link:
    - The chosen-photo row inside the open cluster shows a 96 px `FaceThumb` of the crop. Its caption says whether it is a face crop ("Ảnh cắt khuôn mặt...") or a legacy whole frame. It also has an "Xem khung hình" link.
    - Every tile that has a valid `frameUrl` gets a small frame icon link at the top left, next to zoom.
    - Both links use `target="_blank" rel="noopener noreferrer"` and `href=normalizeApiAssetUrl(path)`.
    - `frameLinkPath` accepts only a same-origin `/api/...` path. It rejects absolute or protocol-relative URLs, `javascript:`, `.`/`..` segments, `//`, and encoded `.`, `/` and `\`.
  - Crop size: thumbnails stay at grid or 96 px size, which is smaller than the 288-384 px crops. The zoom dialog opens at natural size (1x) as before, and 2x/3x only when the operator picks it.
  - Accessibility:
    - While registering, the whole tile is a real `<button aria-pressed>` ("Chọn ảnh khuôn mặt N làm ảnh chính"), so keyboard users can choose the avatar. Before, only mouse users could.
    - When not registering, that button is out of the tab order and the existing zoom button stays the keyboard path.
    - The overlays are `pointer-events-none`.
    - The chosen-photo label is `aria-live="polite"`.
- **API/event contracts added or changed:** none beyond plan section 9. The client consumes: `observationId`, `faceId` and `frameUrl` on photos; `clusterObservationIds` and `sourceObservationId` on dismiss, merge and quick-register; `lookup?faceId=`.
- **Schema/migration changed:** no

  - No new data is stored in the browser.
  - The frame link only targets same-origin API paths, so the session cookie never goes to a foreign host from a server-supplied URL.
  - The whole frame can show other people. That follows the owner's decision 4, and the image route decides access (viewer and up).

## Risks and follow-up

- **Known risks:**
  - **The backend must not retire by `clusterLogIds` when `clusterObservationIds` is present.** For a face-level cluster, `clusterLogIds` lists frames that also hold other people's faces in other clusters. A server that retires or adjudicates by log would retire the companion's face too, which undoes plan section 4 ("Resolving one face in a two-person frame leaves the other face in its own group").
  - The "Xem khung hình" link is a top-level navigation, not a `fetch`. It works only if `GET /api/logs/:id/image` accepts the operator session cookie on a plain GET, with no custom header, bearer token or CSRF header, and serves the image inline. With a cross-origin custom backend (`getApiBaseUrl()`), whether the cookie goes with the navigation depends on its `SameSite` setting.
- **Unresolved questions / what the backend must provide that the contract does not state:**
  1. `frameUrl` must be a relative same-origin path matching `^/api/[A-Za-z0-9._~%/-]+(\?[A-Za-z0-9._~%&=-]*)?$`, for example `/api/logs/<logId>/image`. An absolute URL or NVR link gets no link. An NVR clip link (plan section 4, "or the NVR clip") needs its own field or an `/api/...` redirect route.
  2. `cluster.primaryPhoto` should equal one tile's `photoSnapshot` (the crop URL for face clusters), so the default chosen tile is the one the server prefers. Otherwise the first tile is used.
  3. The `lookup?faceId=` response must contain the target face as a photo with `faceId` or `observationId: "face:<id>"`. A 404 or 410 shows a notice; other non-2xx statuses show the error state.
  4. `sourceObservationId` should be validated as one of `clusterObservationIds`. The client always sends a matching pair.
- **Proposed hotspot changes (not made):**
  - `src/types.ts` (INT): add `clusterObservationIds?: string[]` and `sourceObservationId?: string` to `QuickRegisterStrangerPayload`. The modal builds untyped payloads, so nothing breaks today.
  - `src/App.tsx` (next frontend wave, or INT if preferred): `parseStrangerDeepLink` should map `#strangers/face/<faceId>` to `{ open: true, faceId }` and pass `initialPreselectedFaceId`. Today that hash is parsed as `logId = "face/<faceId>"`, and the lookup answers 404 with a notice, which is harmless. It is not needed until a backend link generates face URLs.
- **Dependencies on other agents/commits:** the INT agent's per-face routes (`clusterObservationIds`/`sourceObservationId` handling, `faces/:id/image`, `lookup?faceId=`, photos with `observationId`/`faceId`/`frameUrl`).
- **Requested integration action/order:** merge after `release/per-face` contract `e8acae7`, in any order relative to the db and INT branches. The client works against both old and new servers. Rerun the full unit tests and the SQLite + PG integration gates on the integrated branch.
