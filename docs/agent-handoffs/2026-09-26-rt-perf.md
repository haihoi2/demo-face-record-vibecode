## Changes

- **`faceEmbedding.ts`:**
  - `FACE_DETECTOR_VARIANT=fp32|int8` (default fp32; blank/unknown = fp32 + `variantWarning`) selects
    `det_10g_int8.onnx`; explicit `FACE_DETECTOR_MODEL` still wins.
  - No INT8 recogniser: ArcFace INT8 failed the bar. `FACE_MODEL_VARIANT` / `FACE_RECOGNIZER_VARIANT` are ignored and
    reported in `variantWarning` (logged at load).
  - `faceModelTagFor(file)` = `arcface_<file without .onnx>` (identical to `server.ts faceModelTag()` today, so FP32
    templates stay `arcface_w600k_r50`). A recogniser forced by explicit file gets its own tag; `buildGallery` drops foreign tags.
  - `getFaceEngineInfo()` now reports the files actually loaded plus `detectorVariant`, `recognizerVariant`, `modelTag`,
    `variantWarning`, `detectUpscale` (additive fields on `/api/face-engine/status` `info`).
  - Fail closed: a selected file missing/corrupt fails the load; no fallback to another variant (verified on a gateway:
    `FAIL-CLOSED ... model file missing: /models/det_10g_int8.onnx`).
  - `FACE_DETECT_UPSCALE=none|area|bilinear`, **default `none`**: pictures smaller than the 640 detector input on both axes
    are padded at native resolution instead of stretched with the blocky area resize. Only affects small images (crops,
    tiny uploads); every camera frame, browser capture and stored full frame is downscaled as before.
    Rollback: `FACE_DETECT_UPSCALE=area`. `resizeBilinear()` added for the `bilinear` option.
- **`pipeline/faceCrop.ts`:** `computeFaceCropRect`, `cropFaceFromRgb(Frame|RgbPicture, box)`,
  `cropFaceFromImage(bytes|base64|dataURL, box)`, `cropToDataUrl`, `resolveFaceCropOptions`; env `FACE_CROP_MARGIN` (2.5),
  `FACE_CROP_MIN_PX` (288), `FACE_CROP_MAX_PX` (384), `FACE_CROP_QSCALE` (4), `FACE_CROP_TIMEOUT_MS` (3000).
  The box is in the picture's own pixels (for a Frame: frame/ROI coordinates, as the detector returns them).
- **`scripts/perf/`:** `crop-eval.ts`, `dump-calib.ts`, `quantize.py`, `int8-eval.ts`, `bench-engine.ts` (header of each has usage).
- **Schema/migration:** none. **API:** additive `info` fields only.
- **Security/privacy:** crops shrink stored biometric data (median 14 KB vs ~0.8-2.3 MB frames). No embeddings leave the
  backend. Model files contain quantization scales only; the calibration tensors (biometric derivatives) were deleted.

## Measurements

Data: 260 most recent `access_logs.photoSnapshot` (130 ENTRY 3840x2160, 130 EXIT 1920x1080), exported read-only to a
0700 tmpfs dir and deleted afterwards. Host shared with the live gateway and other agents (load 5-13 on 8 cores);
containers capped at `--cpus 2`, so absolute latencies are inflated; ratios are the robust part.

**Caveat on the stored frames:** they are re-encoded at q8 and carry the annotator's green box (`drawbox`, 1.7x the face,
`t=iw/120` = 32 px at 4K), which sits just outside the face and becomes a thick frame inside a crop. Rows marked
"band inpainted" replace those saturated-green pixels from their neighbours to approximate the raw frames the pipeline
will crop. That is a lower bound, not a raw-frame measurement: raw NVR frames were not used.

Crop encode ~95-107 ms per face under load (ffmpeg spawn dominated). Readings:
- Crop-vs-full-frame cosine (~0.95) is mostly the full frame's fault: on a 4K frame a 90 px face is ~15 px in the
  640 detector input, so its landmarks are coarse; two different crops of the same face agree at 0.96-0.99.
- Misses left at the default: 12 faces not detected on the crop at all (all sizes), 11 re-found but failing the pose
  gate (`clear`) with the crop's sharper landmarks; quality was never the reason.
- **Recommendation:** defaults 2.5x / 288 / 384 / q4 and `FACE_DETECT_UPSCALE=none` (both now the code defaults).
  Enrolling from the capture-time embedding avoids the remaining ~12% (see proposal 3 below).

## Data and deployment

- **Forward migration:** none. **Rollback:** `FACE_DETECTOR_VARIANT=fp32` (default) and/or `FACE_DETECT_UPSCALE=area`,
  restart only; or revert the commits.
- **Backward compatibility:** default model files, tag `arcface_w600k_r50` and all existing templates unchanged. The
  only default behaviour change is `FACE_DETECT_UPSCALE=none` for images smaller than 640x640.
- **Data retention/deletion impact:** crops replace frames once wired (smaller biometric footprint). Scratch exports,
  calibration tensors and per-frame JSON deleted.
- **Deployment/restart required:** no deployment by me; INT8 needs the model file inside the container (proposal 4).

## Risks and follow-up

- **Known risks:** crops lose ~6% of faces (not re-detected) and a further ~5% of enrolment grade vs the full frame, on
  pessimistic data. Crops must be taken BEFORE any annotation: a burned green box inside a crop was the main cause of
  misses. An INT8 detector misses ~1% of usable faces the FP32 one finds; keep it off until the MT shadow comparison.
- **Unresolved questions:** should enrolment from pipeline events use the capture-time embedding (proposal 3)? Is a
  1% detector recall cost acceptable for 3x detector speed (owner/MT)?
- **Dependencies:** none on other W1 branches. TRK/INT consume `cropFaceFromRgb` and the default options.
- **Requested integration action/order (INT, `server.ts` / pipeline wiring; not done by me):**
  1. `faceModelTag()` -> `return getFaceEngineInfo().modelTag;` (same string today; one source of truth).
  2. Persisting a `TrackOutcome` (employee and stranger): `best.crop = await cropFaceFromRgb(best.frame, best.detection.box)`;
     store `cropToDataUrl(best.crop)` as `photoSnapshot`. If it returns null, store no image and count it; never fall
     back to the full frame. Do not run `annotateSnapshotWithBoxes` on crops.
  3. Quick-register/merge of a pipeline event: when the log carries `faceEmbedding` with
     `faceEmbeddingModelTag === faceModelTag()` and `faceEmbeddingQuality >= FACE_ENROLL_MIN_QUALITY` from a clear face,
     enrol that embedding; otherwise fall back to `extractFaces(crop)` as today. This removes the crop re-detection loss
     for strangers (their logs already carry the embedding).
  4. INT8 detector in the container (optional, after shadow): mount `/data/models:/app/models-host:ro` and set
     `FACE_MODEL_DIR=/app/models-host`, `FACE_DETECTOR_VARIANT=int8` (compose, INT-owned). Keep `FACE_ORT_THREADS=2`
     (4 threads were slower under a 2-CPU budget).
  5. `.env.example`: `FACE_DETECTOR_VARIANT`, `FACE_DETECT_UPSCALE`, `FACE_CROP_MARGIN`, `FACE_CROP_MIN_PX`,
     `FACE_CROP_MAX_PX`, `FACE_CROP_QSCALE`, `FACE_CROP_TIMEOUT_MS`.
  6. Merge order: as planned (after STR, before TRK); no conflicts expected (no hotspot touched).
