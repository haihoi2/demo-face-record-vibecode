# Agent handoff: TRK tracker + per-track decision (real-time pipeline, step 2)

## Task

- **Title:** Multi-face tracker and exactly one decision per person per passage.
- **Owner/agent:** TRK (face-engine), W1 of `docs/plans/2026-09-26-realtime-pipeline.md`.
- **Acceptance criteria:**
  - follow several faces across ~8 fps frames, IoU plus motion prediction, embedding tie-break at 0.45;
  - only clear faces of at least 60 px carry evidence; unclear frames keep the track alive;
  - ArcFace runs only when asked (`needsEmbedding`), at most 5 per track;
  - employee as soon as the existing fusion rules pass; stranger at track end with at least 2 usable frames; otherwise insufficient;
  - exactly one `TrackOutcome` per track, plus a `ShadowResult`;
  - unit tests for every scenario in the brief, plus no-face, overload, corrupted input, model mismatch and timeouts;
  - typecheck, unit tests and build all green.
- **Scope explicitly excluded:** wiring into `server.ts` (INT), persistence (DAT), crops (PERF), SCRFD threshold changes (PERF), real-clip acceptance (MT).

- **Files changed:** 4 new files (2 source, 2 tests), about 2,400 lines in total.
- **Behavior changed:** none at runtime. Nothing imports the new modules yet, and every gate is still `legacy`.
- **API/event contracts added or changed:** new module-level TypeScript API only (below). `contracts.ts` is unchanged; proposals are at the end.
- **Schema/migration changed:** none.
- **Environment/configuration changed:** none. Defaults read existing settings through imports: `FACE_MIN_SIZE_PX` via `CLEAR_FACE_LIMITS.minFacePx`, `FACE_CLEAR_MAX_YAW`, and `FACE_STRANGER_CLUSTER_COSINE` via `STRANGER_SAME_PERSON_COSINE`.
- **Security/privacy impact:**
  - Fail closed. An `employee` outcome requires all of the following:
    - `engineReady === true`;
    - `galleryModelTag === engineModelTag`, both non-empty;
    - the tracker's `modelTag` equal to them;
    - valid server-owned thresholds;
    - evidence embeddings of the gallery's length.
  - Otherwise the track ends `insufficient` with basis `context-invalid`. No stranger record is written, so employees are not filed as strangers.
  - Evidence is tagged with its model tag and compared only when the tag equals the gallery's.
  - Embeddings live only while a track is undecided. They are dropped the moment an employee outcome is emitted or the track ends.
  - Snapshots and `pending()` expose counts only. `fused` evidence contains cosines, never vectors.
  - The stranger outcome carries the mean embedding, as the contract requires. It must stay backend-side.
  - Capture quality is not liveness. Nothing here claims presentation-attack detection.

### API for the integrator

```ts
// tracker.ts
new FaceTracker({ gate, modelTag, config?, clock?, idPrefix? })
  .plan(frame, inputs: TrackerInput[]): { needsEmbedding: boolean[]; requests: EmbeddingRequest[] }  // pure dry run
  .update(frame, inputs /* with embeddings for needsEmbedding */): TrackerStep
  .tick(nowMs?): TrackEnd[]     // call on a timer (e.g. every 250 ms) so tracks end when the stream stalls
  .endAll(reason, nowMs?): TrackEnd[]
  .closeEvidence(trackId) / .snapshot()
TrackerInput = { detection: FaceDetection; quality?: number /* faceQuality() */; embedding?: Float32Array; embeddingModelTag?: string }

// trackDecision.ts
new GateTrackSession({ gate, modelTag, context: DecisionContext, trackerConfig?, decisionConfig?, clock?, idPrefix? })
  .plan(frame, inputs) -> embed the faces with needsEmbedding -> .process(frame, inputsWithEmbeddings): { step, results }
  .tick(now?) / .close(now?) / .setContext(ctx) / .contextStatus()
DecisionContext = { gallery: currentGallery(), galleryModelTag: faceModelTag(), engineModelTag: faceModelTag(),
                    thresholds: currentFusionThresholds(), engineReady: faceEngineActive() }
TrackDecisionResult = { outcome: TrackOutcome; shadow: ShadowResult; basis; fusionBasis?; meanCheckRefused? }
```

### Algorithm parameters (defaults in `DEFAULT_TRACKER_CONFIG` / `DEFAULT_DECISION_CONFIG`)

| Parameter | Value | Why |
|---|---|---|
| Motion | alpha-beta constant velocity on (cx, cy, w, h), alpha 0.7 / beta 0.3; velocity re-estimated from the last two observations after a gap (OC-SORT); extrapolation capped at 500 ms | deterministic and cheap; the cap stops hidden faces from drifting away |
| Association | greedy by score (IoU, +1 when embedding cosine >= 0.45), deterministic tie order | with 1-5 faces greedy equals Hungarian in practice |
| Stage 1 / stage 2 | score >= 0.6 at IoU >= 0.3 / 0.3 <= score < 0.6 at IoU >= 0.5 against confirmed/lost tracks only | ByteTrack: low scores keep tracks alive but never start or confirm them |
| New track | score >= 0.6, at most 16 tracks per gate | overload guard |
| Ambiguity | best two candidates within 0.15 IoU, so `tiebreak` embeddings are requested | people crossing |
| Identity guard | cosine < 0.25 against the track's evidence splits the face into another track; 0.25-0.45 is `conflict` (kept, not evidence) | never fuses two people |
| Re-attach | lost/missed track, embedding cosine >= 0.45, within 3 box widths | occlusion followed by a jump |
| Lifecycle | confirmed after 2 hits; tentative dropped after 500 ms missing (no outcome); lost after 1 s; ended after 2 s | per brief |
| Usable (evidence) | `clear === true` and `sizePx >= FACE_MIN_SIZE_PX` (60) and score >= 0.5 | 60 px + frontal rule, re-checked (does not trust `clear` alone) |
| Embedding budget | new track / first 2 frames / selection score +10% / tie-break; max 5 per track, 4 per frame; none after the decision | ArcFace is the cost |
| Selection score | quality x (1 - 0.5 x min(1, abs(yaw)/maxYaw)) | prefers larger, sharper, more frontal faces |
| Decision | best 5 embedded frames, `matchObservations` + `fuseDecision` unchanged, server thresholds (0.55 / 0.45 / 2 / 0.08) | existing rules |
| Track-mean check | quality-weighted mean of the L2-normalised frames must name the same winner, score >= minEvidence, and beat its own runner-up by minMargin | refuse-only; closes the lookalike gap below |
| Stranger | confirmed, not recognised, >= 2 comparable frames, best quality >= 0.25 (mirrors `FACE_STRANGER_MIN_QUALITY`) | else `insufficient` |

- **Covered by the new tests:**
  - single walker decided within 2 usable frames, by multi-agree and by single-strong;
  - two people at once, and two people crossing (motion only, and an ambiguous overlap resolved by embeddings);
  - brief occlusion, and a lost track re-attached by embedding;
  - detector flicker, including low-score frames;
  - faces under 60 px and turned faces never usable or embedded, even when the caller lies;
  - a person lingering for 30 s gets one outcome;
  - stranger decided once at track end;
  - insufficient with fewer than 2 usable frames, and with low quality;
  - embedding budget: 5 per track, 4 per frame, +10% rule, closed after decision;
  - lookalike employees never granted;
  - failures: foreign model tag, engine not ready (and recovery), invalid thresholds, server thresholds respected, malformed gallery templates;
  - corrupted detections, embeddings and frames; wrong gate; out-of-order frames; overload; timeouts and stream gaps; reset on ROI or stream change;
  - determinism; no embeddings in snapshots or fusion evidence.

## Risks and follow-up

- **Known risks:**
  1. **Gap in the existing fusion (applies to legacy too).**
     - `fuseDecision` multi-agree measures the margin between *winning candidates* only.
     - When every frame prefers the same lookalike employee by less than 0.08 (for example 0.69 vs 0.65), it grants.
     - `tests/trackDecision.test.ts` characterises this (`fusedOnly.recognized === true`) and shows the track-mean check refusing it.
     - Legacy scans use `fuseDecision` directly and remain exposed.
  2. **ArcFace CPU cost.**
     - `server.ts` notes about 360 ms per embed on FP32 CPU. At 410 per minute (4 strangers continuously), that is about 2.5 cores.
     - Mitigations: PERF's INT8 path, or `maxEmbeddingsPerTrack: 3` (config; the early-decision path needs only 2).
  3. **Stage 2 is inert with the current detector threshold.** SCRFD drops faces below `FACE_DETECT_THRESHOLD` = 0.5, so the low-score stage only sees 0.5-0.6.
  4. **Repeat outcomes for one person are still possible.**
     - Case: hidden for more than 2 s, or reappearing unclear (no embedding to re-attach) far from the predicted box.
     - Result: a second track, so a second outcome.
     - INT's per-employee grant cooldown should stay in front of the door.
  5. **Sequential evaluation.**
     - A track is re-evaluated after each new evidence frame (at most 5), on the cumulative set.
     - That is fewer looks per passage than legacy's repeated scans, but it is not a single final test.
     - False-accept rate on real impostor clips must be measured by MT (target 0).
  6. **Stranger in view for a long time.** The stranger is reported only when the track ends, which can be 2 s or more after they leave.
- **Unresolved questions:**
  1. Should `rejected-ambiguous` tracks (lookalike employees) at end be `stranger` (current, same as legacy) or `insufficient`? `fusionBasis` is returned so INT can choose.
  2. Should the site's owner approve `maxEmbeddingsPerTrack` 3 vs 5 after PERF's numbers?
- **Dependencies on other agents/commits:** none to build.
  - Imports: `CLEAR_FACE_LIMITS`, `EMBEDDING_DIM`, `facePose` and `iou` (faceEmbedding.ts, PERF); `STRANGER_SAME_PERSON_COSINE` (strangers.ts). PERF must keep these exports.
- **Requested integration action/order:** merge after PERF (plan order).
  - INT wiring per gate:
    1. On each frame, run SCRFD and compute `faceQuality` (aligned crop, cheap) for every face.
    2. Call `session.plan`.
    3. Run ArcFace only for `needsEmbedding` and tag each result with `faceModelTag()`.
    4. Call `session.process`.
    5. Call `session.tick()` every 250 ms. Call `session.setContext(...)` after enrolment, template change, threshold change or engine state change. Call `session.close()` on stop.
  - Shadow mode: log `result.shadow` (SSE `pipeline_shadow_result`) and never act.
  - Live mode:
    - employee: access policy, then door, then log;
    - stranger: existing stranger path (the storage floors and cooldown still apply);
    - insufficient: nothing.

### Proposed changes to files I do not own

1. **`src/server/pipeline/contracts.ts` (INT):**
   - add `modelTag: string` to `TrackUpdate`, since embeddings must carry their model;
   - optionally add `basis?: string` to `ShadowResult` so shadow comparisons show why (`multi-agree`, `rejected-ambiguous`, `context-invalid`, ...).
2. **`src/server/faceFusion.ts` (face-engine owner):**
   - in `fuseDecision`, rule (b) should also require the winner's per-observation margin;
   - for example, add `&& mean(w.evidence.map(e => e.cosine - e.secondCosine)) >= th.minMargin`, with a regression test for two frames at 0.69/0.65;
   - this closes risk 1 for legacy scans as well; the track-mean check can stay as defence in depth.
3. **`src/server/faceEmbedding.ts` (PERF):** allow a per-call detection threshold (e.g. `detectFaces(input, { threshold: 0.3 })`) so the pipeline can feed low-score boxes to stage 2 without changing legacy behaviour.
