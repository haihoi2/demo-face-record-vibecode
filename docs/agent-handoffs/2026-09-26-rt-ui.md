## Risks and follow-up

- **Known risks:**
  - Operators lose the dashboard live view by design; the gate face strip depends on the app's access-log
    list (SSE) and shows only rows with an image.
  - The ROI still is full resolution (4K on ENTRY): a ~1-3 MB JPEG per editor open.
  - Crop vs frame is inferred from the image (aspect >= 1.45 or side > 800 px = frame).
  - `CameraDashboard.tsx` still opens its own `EventSource` (pre-existing; not centralised in this task).
- **Unresolved questions:** should the dashboard "Quét"/"Quét Ngay" manual scans stay once gates are `live`?
- **Dependencies on other agents/commits:** none to merge; INT/DAT changes below make the new UI fully effective.
- **Requested integration action/order (proposals, not implemented):**
  1. **INT - `roi` on streams.** Accept, validate and persist optional `roi` on stream records
     (`sanitizeStreamSource`, POST/PUT `/api/camera-streams/:gate/streams[/:id]`, POST `/config`):
     `roi?: { x: number; y: number; w: number; h: number } | null`, fractions of the picture,
     `0 <= x,y`, `0.05 <= w,h <= 1`, `x+w <= 1`, `y+h <= 1` (clamp or 400), 4 decimals; `null` or the
     whole picture = delete the field. Return it on the stream in the response (the UI reads it back).
     StreamReader converts it to `Frame.roi` pixels: `[round(x*W), round(y*H), round(w*W), round(h*H)]`.
     Role: existing rule (operator) + CSRF; audit the change.
  2. **DAT - `types.ts`:** add to `GateStreamSource`: `roi?: { x: number; y: number; w: number; h: number } | null;`
     and to `GateWatchRuntime`:
     `pipelineState?: { status: "starting"|"streaming"|"stale"|"reconnecting"|"stopped"; fps: number; newestFrameAgeMs: number|null; reconnects: number; lastError?: string; since: string };`
     `pipelineStats?: { lastDecisionLatencyMs?: number; decisions?: number };`
     (the UI keeps its own defensive readers, so no UI change is needed when these land).
  3. **INT - runtime:** include `pipelineState` (latest `SourceState` minus `gate`) and `pipelineStats`
     in `gateWatchRuntime()` for REST and `gate_watch_state` SSE; no URLs/credentials in `lastError`.
  4. **INT - backend privacy follow-up (owner decision):** the browser no longer uses
     `GET /api/camera-streams/mjpeg` - propose removing it; restrict `GET /api/camera-streams/snapshot`
     to operator+ (viewer can fetch a full frame today) and audit it as a footage read; consider
     dropping the `url` query override on both routes.
  5. Merge order unchanged: UI after TRK, before INT wiring.
