## Changes

- **Files changed:** the six files above.
- **Behavior changed:**
  - Webhook tab gains `NotificationChannelsSection`, rendered only when `hasRole(session, "admin")`, between the
    configuration grid and the network-IP card. All calls via `operatorJsonFetch` (credentials, CSRF retry, 401 sign-in).
    Toggle (role="switch"), test, edit (ModalDialog), delete (alertdialog confirmation) and routes (explicit "Lưu nơi gửi")
    apply only after a 2xx `success: true`; a refusal shows the server's `error` (DEST_* text under the URL field when
    `field: "url"`). The typed URL is cleared (draft reset) after a confirmed create/edit; it is never rendered, logged or
    stored. Parsing never copies a `url` field from a reply. Chips derive from the latest `routes` reply.
  - Presence tab gains a collapsible "Cài đặt cổng" block (loads on first expand, reloads with "Làm mới"). Admin: mode as
    three aria-pressed buttons applied immediately (PUT `{ mode }`), "Đang báo" behind an alertdialog with the agreed text;
    form for hours (two `type=time` inputs), minimum seconds, "Gộp tin mỗi" in minutes, "Chờ nhận diện"; save sends only
    changed fields; "Đặt lại theo .env" sends `{ field: null }`. Operator: read-only list with "Đã lưu"/"Theo .env" tags.
    Viewer/signed out: nothing rendered and no request. After a confirmed save the status strip is reloaded.
  - Presence header copy no longer says the page "không gửi cảnh báo" (P3a live mode exists); it now says only gates in
    "Đang báo" send messages.
- **API/event contracts added or changed:** none (consumes contract section 2 as written).
- **Schema/migration changed:** none.
- **Environment/configuration changed:** none.
- **Security/privacy impact:** UI-only. No URL, token or embedding shown/stored; no localStorage/sessionStorage in the new

## Risks and follow-up

- **Known risks:**
  - "Đặt lại theo .env" for `mode` could switch a gate to live if .env says live; the UI asks for confirmation with a
    generic text because it cannot know the .env value.
  - The status strip's period filter labels in src/utils/presence.ts still hard-code "07:00-19:00" (not an owned file);
    with per-gate hours they may be wrong. Suggest a follow-up.
- **Unresolved questions / assumptions (contract unclear):**
  1. Integer or decimal: assumed `alertWindowSeconds` is whole seconds (minutes x 60, rounded) and `alertHoldSeconds`,
     `minSeconds*` may be decimals within range. If the server requires integers for `alertHoldSeconds`, it will refuse
     and the UI shows its text.
  2. `POST .../:id/test` with HTTP 200 and `success: false` is shown as a failure with `error` or the chat `statusCode`.
  3. `field` in an error is mapped to the form field of the same name (`name`/`url`; settings field names); other errors
     are shown under the form.
  4. "Dùng cho" chips are derived from `routes` (fresher after a routes PUT) rather than each channel's `usedFor`.
  5. Mode changes apply immediately (one PUT per click), the other fields through "Lưu"; reset is immediate per field.
  6. URL shape check accepts http and https; https enforcement (WEBHOOK_ALLOW_HTTP) is left to the server.
  7. PUT routes sends only the changed keys.
- **Dependencies on other agents/commits:** backend P3b routes (Hermes) and app_settings storage (data-migrations agent).
- **Requested integration action/order:** merge after the backend P3b routes; then rerun lint/test/build on the integrated
  branch and do a dev browser check of both tabs (admin, operator, viewer) before any staging deploy.
