- **Schema/migration changed:** no
- **Environment/configuration (read by the module, all optional; blank = unset):**

  | Variable | Used by | Meaning |
  |---|---|---|
  | `CAMERA_ALLOWED_HOSTS` | camera, tcp-probe | comma list of hosts, `*.suffix`, IPs, CIDRs (IPv4 dotted quad only, so `10/8` is invalid, not 0.0.0.10) |
  | `WEBHOOK_ALLOWED_HOSTS` | webhook | same |
  | `DOOR_ALLOWED_HOSTS` | door | same |
  | `CAMERA_DENIED_HOSTS`, `WEBHOOK_DENIED_HOSTS`, `DOOR_DENIED_HOSTS`, `NET_DENIED_HOSTS` | per policy / all | refused even if allowed |
  | `WEBHOOK_ALLOW_HTTP` | webhook | `true` also accepts `http://` (default https only) |

  Semantics: a set list is exclusive (the destination must match it: a listed host name trusts whatever it resolves
  to; an unlisted name must resolve only into listed IPs/CIDRs), and the always-refused set still applies. Unset:
  camera / door / tcp-probe accept private (RFC 1918, CGNAT 100.64/10, 198.18/15, ULA fc00::/7) and public;
  webhook accepts public only (`DEST_PRIVATE_WEBHOOK`). Documentation ranges (192.0.2/24, 198.51.100/24,
  203.0.113/24, 2001:db8::/32) count as public (never routed; useful as test fixtures). A list whose entries are all
  invalid matches nothing (fail closed); log `invalidPolicyEntries()` at startup.
- **Always refused:** 0.0.0.0/8 and `::`; 127/8, `::1`, `localhost`, `*.localhost`, `localhost.localdomain`,
  `ip6-localhost`; 169.254/16 and fe80::/10; metadata 169.254.169.254, 169.254.170.2, 100.100.100.200,
  fd00:ec2::254 and `metadata.google.internal` / `metadata` / `instance-data[.ec2.internal]`; 224/4, ff00::/8,
  255.255.255.255; 240/4, 192.0.0/24, 192.88.99/24, Teredo 2001::/32, 100::/64, anything outside 2000::/3 among
  non-special IPv6; the gateway's own interface addresses (`os.networkInterfaces()`, so its eth0 IP cannot reach its
  own ports); `host.docker.internal` / `gateway.docker.internal`. IPv4-mapped, SIIT, IPv4-compatible, NAT64
  (64:ff9b::/96, 64:ff9b:1::/48) and 6to4 (2002::/16) are judged by the IPv4 address they carry.
- **Parsing:** inet_aton spellings (`2130706433`, `0x7f000001`, `0x7F.0.0.1`, `0177.0.0.1`, `0177.1`, `127.1`), trailing
  dot, upper-case scheme and host, explicit ports, bracketed IPv6. Refused as `DEST_BAD_URL`: numeric-looking hosts
  that are not valid IPv4 (`08.1`, `1.2.3.256`), `%` in the host (incl. IPv6 zone ids), backslashes, whitespace,
  control or non-ASCII characters anywhere (WHATWG/FFmpeg/libc parser differentials: `rtsp://evil\@127.0.0.1`,
  circled-letter `localhost`), port 0 / > 65535, and any URL whose naive authority split (last `@`, first `/?#`,
  as FFmpeg's `av_url_split`) names a different host than WHATWG `URL`. `rtsp://127.0.0.1@evil` dials `evil`, and
  `evil` is what gets checked.
- **DNS:** names are resolved (default `dns.promises.lookup(all, verbatim)`, 3 s timeout) and EVERY address must pass
  (one `127.0.0.1` among public answers refuses). Resolver error / empty / garbage / timeout = `DEST_UNRESOLVED`.
  Rebinding limit: check-then-dial resolves twice. `addresses` is returned for pinning; `createGuardedLookup` closes
  the gap for Node HTTP/TCP clients; FFmpeg resolves by itself, so camera allowlists should list IPs.
- **Security/privacy impact:** defensive only. No credential ever returned (tested with a planted password in
  userinfo, path and query).

## Wiring for the integrator (server.ts at `d8fcd13`, read-only survey)

Build the policies once at startup and log problems (host names only, no URLs):

```ts
import { checkDestination, policyFromEnv, invalidPolicyEntries } from "./src/server/netGuard";
const NET_POLICY = { camera: policyFromEnv("camera"), probe: policyFromEnv("tcp-probe"), webhook: policyFromEnv("webhook"), door: policyFromEnv("door") };
for (const [k, p] of Object.entries(NET_POLICY)) {
  const bad = invalidPolicyEntries(p);
  if (bad.length) console.warn(`[NetGuard] ${k}: ignored invalid entries: ${bad.join(", ")}`);
  if (!p.allow && process.env.NODE_ENV === "production" && k !== "webhook") console.warn(`[NetGuard] ${p.allowEnvVar} not set: private + public destinations accepted`);
}
```

Response shapes: **write refused** → `400 { success:false, code, error: reason, field, streamId? }` and nothing is
saved. **Stored destination refused at use** → `409 { success:false, code, error: reason, streamId? }` (config
conflict, not a bad request). **Background sends** (webhook, door) → no fetch; a log entry with `success:false`,
`error: reason`, `blockedCode: code`, saved and broadcast like a network failure. Exception on write only:
`DEST_UNRESOLVED` (DNS down or a not-yet-registered name) saves with `warning: { code, reason }` — the dial-time
check still refuses it, fail closed.

### Recommended production values

- `CAMERA_ALLOWED_HOSTS=192.168.60.1,192.168.10.40` (the NVR and the EZVIZ, by IP: no DNS, no rebinding). Without it
  the camera default also accepts the Docker networks (172.16/12: `smartface-postgres-18`, other projects' containers)
  and the host itself through its LAN address, and test-stream can still probe them. Widen to
  `192.168.60.0/24,192.168.10.0/24` only if the owner wants to add cameras without an env change.
- `DOOR_ALLOWED_HOSTS=<the door controller's IP>` once its stored host is checked (below).
- `WEBHOOK_ALLOWED_HOSTS` unset (public only) if the stored webhook host resolves public **from inside the gateway
  container**; if the site DNS answers a private address for it, set `WEBHOOK_ALLOWED_HOSTS=<that host name>`.
- `NET_DENIED_HOSTS=192.168.6.52` (the Docker host's LAN address: OpenResty, this gateway on 8080 and other
  projects). Moot once the allowlists above are set, harmless as a backstop.
- `WEBHOOK_ALLOW_HTTP` unset.

## Production issues found while surveying (no production code changed)

- **N1 door token in server logs — medium.** With `authHeaderType=QUERY_PARAM` the token is appended to `targetUrl`
  (L2341-2344), which is then printed by `console.log` / `console.error` (L2446, L2451) and stored as
  `door_api_logs.url` (L2405). API responses redact it (`sanitizePublicJson` → `redactedUrl`), the container log and
  the DB row do not. Fix with the wiring of item 15: log/store `withoutUserinfo` + `redactedUrl(targetUrl)`.
- **N2 scan-rtsp body `url` — medium (operator).** `performGateScan` L4358 dials a caller-chosen RTSP URL, the same
  class as F1 which was fixed for snapshot/mjpeg only. Covered by item 8.
- **N3 redirects — medium (admin).** Webhook and door `fetch` follow redirects by default; an allowed host can bounce
  the request to an internal address. Covered by items 13 and 15 (`redirect: "manual"`).
- **N4 door test `testConfig` — low (admin).** `POST /api/door-controller/test` spreads any `body.testConfig` field
  into the live config object for the duration of the call (L3072-3080); whitelist the fields. The destination part is
  covered by item 15.
