## The guard module (`src/server/netGuard.ts`)

- `checkDestination(rawUrl, policy | "camera" | "webhook" | "door" | "tcp-probe", deps?)` →
  `{ ok: true, url /*no userinfo*/, host, port, addresses }` | `{ ok: false, code, reason, host? }`;
  also `policyFromEnv`, `parseHostList`, `invalidPolicyEntries`, `classifyAddress`, `createGuardedLookup`, `withoutUserinfo`.
- Codes: `DEST_BAD_URL`, `DEST_SCHEME`, `DEST_LOOPBACK`, `DEST_UNSPECIFIED`, `DEST_LINK_LOCAL`, `DEST_METADATA`,
  `DEST_MULTICAST`, `DEST_RESERVED`, `DEST_SELF`, `DEST_DENIED`, `DEST_PRIVATE_WEBHOOK`, `DEST_NOT_ALLOWED`,
  `DEST_UNRESOLVED`. `reason` is Vietnamese and names at most the host and the env variable to change.
- Always refused (even if listed): loopback incl. `localhost`/`*.localhost`, 0.0.0.0/8 and `::`, link-local,
  metadata (169.254.169.254, 169.254.170.2, 100.100.100.200, fd00:ec2::254, `metadata.google.internal` …),
  multicast/broadcast, reserved ranges, the gateway's own interface addresses, `host.docker.internal`; IPv4-mapped,
  SIIT, compatible, NAT64 and 6to4 forms are judged by their IPv4. Every inet_aton spelling (`2130706433`,
  `0x7f000001`, `0177.1`, `127.1`, trailing dot), bracketed IPv6 and userinfo tricks are handled; `DEST_BAD_URL` for
  backslash, `%`, whitespace/control/non-ASCII, port 0, and any WHATWG-vs-FFmpeg authority disagreement. EVERY
  resolved address must pass (3 s DNS timeout).
- Env (blank = unset): `CAMERA_ALLOWED_HOSTS` (camera + test-stream), `WEBHOOK_ALLOWED_HOSTS`, `DOOR_ALLOWED_HOSTS`,
  `CAMERA_/WEBHOOK_/DOOR_DENIED_HOSTS`, `NET_DENIED_HOSTS`, `WEBHOOK_ALLOW_HTTP`. A set list is exclusive. Unset:
  camera/door/test-stream accept private (RFC 1918, CGNAT, 198.18/15, ULA) + public; webhook public only, https only.
  Documentation ranges (192.0.2/24 …) count as public. An all-invalid list refuses everything; invalid entries are
  logged at startup.

## Risks and follow-up

- **Known risks:** DNS rebinding for host-name destinations between the check and the FFmpeg/fetch dial (a camera
  allowlist by IP avoids it; `createGuardedLookup` exists for Node HTTP clients; `fetch` has no lookup hook without
  an undici Agent). The unset camera/door defaults accept the Docker networks, so set the allowlists in production.
  Gate config POST awaits the check between load and save (the same race window as before for concurrent
  full-config posts). The watcher backs off exponentially on a refused stream instead of idling (accepted for this release).
- **Unresolved questions:** exact camera IPs vs /24 subnets (owner); live webhook/door hosts (INT check above).
- **Dependencies on other agents/commits:** none. MT: run the security suite with `CAMERA_ALLOWED_HOSTS=192.0.2.0/24,<harness>`.
- **Requested integration action/order:** INT merges `feat/rt-net` into `release/rt-pipeline` and reruns unit,
  integration (SQLite + PostgreSQL) and MT security from the integrated branch.
