# Review: SmartFace Gate Watch, main @ 89c7df0 (v1.1.0-rt.1), work since 2026-09-24

Read-only review by a review agent (2026-09-27), filed by the integrator. Evidence is `file:line`
on the checkout above. Verified by the integrator on the live dev gateway before filing:
anonymous `GET /Api/employees` answered **200** (finding 1.2); `FACE_ENGINE` is not set on the host
(1.1); the client-threshold path exists at server.ts:1607-1612 (1.1).

**Headline.** The pipeline itself is well built and cannot act in shadow mode. The severe problems
are in the legacy/shared layer: (1) the fail-closed auth boundary is case-sensitive while Express
routes case-insensitively, so `POST /API/lock/unlock` reaches the unlock handler with no session;
(2) request bodies on `/api/recognize-face` and `scan-rtsp` can lower the single-observation accept
threshold; (3) compose never sets `FACE_ENGINE`, so a model-load failure silently hands door
decisions to the demo hash matcher. Items 1-3 are S-effort fixes and go out first (hotfix
`fix/auth-case`).

## 1. Security invariants

### 1.1 No browser/demo/hash decision may authorise the door
- VIOLATION (high, latent): `FACE_ENGINE` unset → `auto` → hash matcher decides when ONNX is not ready
  (server.ts:1531-1536, 1590-1594, 7901-7981; localBiometrics.ts:209-243); the watcher idles only for
  `unavailable`, not `hash` (5118-5120). Fix: production ⇒ `onnx`; watcher idles unless `onnx`.
- VIOLATION (medium): `currentFusionThresholds(clientConfig)` lets `req.body.config.localModel.similarityThreshold`
  lower `acceptSingle` on `/api/recognize-face` (8425→7874) and `scan-rtsp` (4941→4564); `config.engineMode`
  switches the engine per request (7823). Fix: server config + env only.
- HOLDS: shadow cannot act (5526-5536, `crops:false` 5460, `live` downgraded mode.ts:18-21); Gemini identity
  stripped unless `ALLOW_SIMULATED_RECOGNITION` (8104-8118); browser unlock removed (0181a25).
- PARTIAL (privacy): `HYBRID_AUTO` + `GEMINI_API_KEY` sends full frames to Google when ONNX finds no face
  (7985-8064). Recommend `LOCAL_BIOMETRIC` default when the ONNX engine is active.

### 1.2 RBAC and audit
- VIOLATION (critical): case-insensitive routing vs case-sensitive boundary (server.ts:874-889, 793-802;
  auth.ts:116-122). `/API/...` skips the boundary for every route that relies on it alone (lock/unlock,
  recognize-face ingest, config/ai, door-controller/config, webhook/config, camera-streams config/scan/test,
  employees create/delete/merge, notifications/clear, events SSE); mixed case after `/api/` downgrades role
  lookups to `viewer` and skips `requireInternalToken` for `/api/System/db-info`. Fix: case-sensitive routing
  + lower-cased boundary and `canonicalApiPath` + regression tests.
- PARTIAL: rules table gaps (`/api/network/ip-info` viewer; door/webhook logs viewer; `client-log` routes let an
  admin inject log rows). PARTIAL audit: `/api/logs/:id/image` and `/api/logs/clear` unlogged; no audit table (MT F6).
- HOLDS: sessions, CSRF, scrypt, lockout, timing-equal login; note `429 ACCOUNT_LOCKED` is a username oracle.

### 1.3 SSRF / outbound destinations
All user- or config-supplied dial sites are guarded by netGuard (grabRtspFrame 3630-3640, test-stream
3769-3801, stream/config saves 3300-3503, webhooks 2056-2072/2330-2346 with manual redirect, door 2522-2535,
RECORDING_NVR_URL once at startup 6886-6892, pipeline start 5422-5430). Unguarded, not user-controlled:
`/api/network/ip-info` (Internet egress, dead cloud-era code, 2850-2944). Gaps: DNS rebinding for host-name
cameras (documented; `createGuardedLookup` unused); unset camera/door lists accept RFC1918 — production must set
`CAMERA_ALLOWED_HOSTS` (it does since v1.1.0-rt.1). Commit d39dc25's title overstates: scan-rtsp body `url`
remains (4533-4541), now guarded and operator-only.

### 1.4 Credentials
- VIOLATION (medium): door token reaches `door_api_logs.requestHeaders` when `CUSTOM_HEADER` has a blank name
  (2453 vs 2490-2492). Fix: mask by value/actual key.
- Plaintext at rest: door token, RTSP logins in SQLite/JSON under the data dir; PG door table unused (db.ts:2673-2750).
- FFmpeg argv carries RTSP URLs (documented). `redactRtsp` (recording.ts:134-136) misses `rtsps://`, `http(s)://`,
  passwords containing `@`/`/`; `redactCredentials` (streamReader.ts:137-139) is scheme-agnostic — unify.
- `sanitizePublicJson` (835-871) is the last line of defence; key-name based.

### 1.5 Fail-closed
HOLDS for `FACE_ENGINE=onnx`, door without token, pipeline without context/tag, lookalike hotfix. VIOLATION for
`FACE_ENGINE` unset (1.1).

### 1.6 Biometric data
DENIED rows store full embeddings + annotated frames, always mirrored to the gateway disk (SQLite mirror
db.ts:2231-2262; pretty-printed JSON template mirror db.ts:3790-3794, undocumented). No encryption at rest, no
retention job, no per-row delete/export. Trace columns exist but server.ts never writes them (dead schema until
live). Shadow keeps embeddings only in worker memory while a track is open (HOLDS).

### 1.7 Immutable history
Stranger resolution paths append and touch no `access_logs` row (HOLDS, tested). VIOLATION (medium):
`POST /api/employees/merge` rewrites historical rows (6614-6633; db.ts:1795-1833) with no provenance. Bug:
DENIED ids are `"LOG-"+Date.now()` (4403) → same-ms collisions dropped by `ON CONFLICT DO NOTHING`.
`saveAccessLog` return ignored (4334, 4420).

## 2. Structure rule (separate engine flow)
Structurally separate: own modules, worker per gate with own ONNX sessions, `PIPELINE_*` mapped to `FACE_*` only
inside the worker env, `legacy` default, no DB writes in shadow, additive SSE/runtime fields. Read-only coupling
to the legacy gallery/thresholds/tag is by design. Two violations: (a) `FACE_DETECT_UPSCALE` default changed to
`none` in the shared engine (faceEmbedding.ts:244-249, commit 09790f0, dated before the rule) — needs owner
sign-off or revert to `area` with `none` set only via `pipelineWorkerEnv`; (b) runtime contention: the reader's
FFmpeg is not niced and competes with legacy grabs. Divergence: `desiredPipeline` ignores `gate.enabled`
(5407-5415). Operational trap: `PIPELINE_DETECTOR_VARIANT=int8` needs the INT8 file in the model dir (the host
override mounts it; not in the image).

## 6. Operational risks (ranked)
Soak: (1) `/API/...` bypass exploitable on the LAN port now; (2) INT8 file presence (mounted via host override);
(3) CPU contention, manual rollback rule; (4) NVR session budget unknown; (5) at <2 fps processed tentative tracks
expire — the soak may measure little; (6) 4K ROI frames ~25 MB, worker RSS 0.3-0.4 GB/gate, restart loses open
tracks; (7) PG fallback divergence. Before `live`: (8) live needs crop persistence, trace columns, access-policy
step, cooldowns, storage floors, stopping legacy grabs per gate, `gate.enabled`; (9) fix 1.1 first; (10) DNS
rebinding — allow cameras by IP; (11) Gemini frame export; (12) `express.json({limit:"50mb"})` on the login route.
